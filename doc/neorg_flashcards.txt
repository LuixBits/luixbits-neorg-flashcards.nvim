SETUP                                               *neorg-flashcards-setup*

Install the plugin on Neovim 0.10.4 or newer, then configure at least one
schema:
>
  local presets = require("neorg_flashcards.presets")

  require("neorg_flashcards").setup({
    flashcards_dir = vim.fn.expand("~/notes/flashcards"),
    default_file = vim.fn.expand("~/notes/flashcards/cards.norg"),
    default_kind = "japanese",
    schemas = presets.only("japanese"),
    leech_threshold = 8,
    ui = {
      show_shortcuts = true,
      rating_highlights = {
        again = { link = "DiagnosticError" },
        hard = { link = "DiagnosticWarn" },
        good = { link = "DiagnosticOk" },
      },
      heatmap_highlights = {
        [0] = { link = "NonText" },
        [1] = { link = "Comment" },
        [2] = { link = "DiagnosticHint" },
        [3] = { link = "DiagnosticInfo" },
        [4] = { link = "DiagnosticOk" },
      },
    },
  })
<

Use `presets.only("chinese")` for Chinese, or pass a custom `schemas`
table. Neorg is optional. Card storage and collection scans always use
`.norg` files, but the plugin reads those files directly.

When Neorg is installed through lazy.nvim, install LuaRocks first. The
flashcard-only installation does not need it. See the current instructions:
https://github.com/nvim-neorg/neorg#lazy.nvim

`default_file` must be inside `flashcards_dir`, which is also the card-form
write boundary. A current `.norg` file outside it is rejected
instead of receiving a card. A custom `history_file` must be a separate
`.jsonl` file inside the root, so history cannot be appended to a card source.
Unknown setup, scheduling, UI, schema, and field options are rejected so
configuration typos fail visibly.

Setup creates `flashcards_dir` when absent and pins its resolved directory for
the current setup session. If that root is moved, replaced, or retargeted
through a symlink, collection commands fail rather than following the new
path. After an intentional move, restore the directory and call setup() again,
or restart Neovim.

`ui.show_shortcuts = true` displays compact hints in the hub, review window,
and card form. Set it to false to hide the persistent chrome; mappings and `?`
contextual help remain available.

`ui.rating_highlights` configures the Again, Hard, and Good rating groups.
Their defaults link to DiagnosticError, DiagnosticWarn, and DiagnosticOk so
the review UI follows the active colorscheme. If a theme makes those colors
indistinguishable, replace a link with exact attributes such as
`again = { fg = "#ff5f5f", bold = true }`.

`ui.heatmap_highlights` configures activity levels 0 through 4. The defaults
link to NonText, Comment, DiagnosticHint, DiagnosticInfo, and DiagnosticOk.
The glyph changes with activity too, so these links are not expected to form
a guaranteed light-to-dark gradient in every theme.

The repository's NVF module exposes `programs.nvf.neorg-flashcards`. Its
keymap options are:

  keymaps.enable        Add module-managed keymaps when true.
  keymaps.prefix        Exact key that opens the hub.

With `enable = true` and `prefix = "<leader>nc"`, the module creates one
global mapping: `<leader>nc` opens |:Flashcards|.

CONFIGURATION                              *neorg-flashcards-configuration*

Top-level options:

  flashcards_dir           Collection root and card-write boundary.
  default_file             .norg file used outside another collection file.
  default_kind             Schema used when add has no kind argument.
  schemas                  Non-empty map of card schemas.
  history_file             Optional .jsonl ledger inside the collection root.
  leech_threshold          Positive integer; default 8.
  scheduling               Interval options listed below.
  ui.show_shortcuts        Persistent compact hints; default true.
  ui.rating_highlights     Again, Hard, and Good Neovim highlight tables.
  ui.heatmap_highlights    Activity highlight tables at levels 0 through 4.
  on_review                Optional callback after a source change persists.

Every scheduling value must be a positive finite number:

  scheduling.again_minutes       10       Again delay
  scheduling.hard_hours           6       first Hard interval
  scheduling.good_days            3       first Good interval
  scheduling.starting_ease        2.5     new-card ease
  scheduling.min_ease             1.3     lower ease bound
  scheduling.max_ease             2.8     upper ease bound
  scheduling.max_interval_days  365       Hard and Good interval cap

`min_ease` must not exceed `starting_ease`, and `starting_ease` must not
exceed `max_ease`. `good_days` must not exceed `max_interval_days`.

Schema names start with a lowercase letter and may contain lowercase letters,
numbers, `_`, or `-`. Each schema needs a non-empty `fields` list and an
explicit `front` naming one of those fields. Field keys follow the same rule
without `-`, are unique inside the schema, and cannot use scheduler-owned
metadata names. String field options are `label`, `title`, `default`,
`placeholder`, and `help`; `required` and `reveal` are booleans.

`on_review(event)` receives a copy after the source change is persisted. The
event has `type` (`review` or `card_state`), an action in `event.event`,
`card_id`, `path`, and a timestamp. `rated` events also carry `rating`,
`before`, `after`, duration, hint, and session data.
The callback cannot cancel the change. A history append may still be queued
for retry. Callback errors do not stop review. Compatible releases may add
fields.

PRIMARY COMMAND                                 *neorg-flashcards-commands*

                                                        *:Flashcards*
:Flashcards [route]
        Open the Overview page when no route is supplied. Command-line
        completion lists routes and review scopes. This is the plugin's only
        Ex command.

  :Flashcards overview
  :Flashcards cards
  :Flashcards stats
        Open the hub at Overview, Cards, or Stats.

  :Flashcards review due
  :Flashcards review all
  :Flashcards review file
  :Flashcards review tag [tag]
  :Flashcards review score [again|hard|good|new]
        Start a due, cram, current-file, tag, or score review. Every scope
        excludes suspended and buried cards. Missing tag or score arguments
        are prompted for. The current-file scope requires a saved file inside
        `flashcards_dir`, because ratings update that source.

  :Flashcards add [kind]
        Open the card form for the current `.norg` file, or for `default_file`
        from another buffer. Both targets must be inside `flashcards_dir`.
        The target is checked against the pinned collection root before the
        form opens and again when it is written.
        Uses `default_kind` when [kind] is omitted. The destination is shown
        above value-only fields; labels, required marks, placeholders, and
        validation errors cannot be edited. Backspace, word deletion, and
        Delete stop at the current value's boundaries.

        In Insert mode, Enter advances and saves and closes from the last
        field; Tab / Shift-Tab cycle fields. Ctrl-S saves and closes, while
        Ctrl-N saves and starts another card. In Normal mode, j / k select a
        field and Enter or i edits it. q / Esc confirms before discarding a
        changed draft, and ? shows the complete current shortcuts. Fields are
        currently single-line.

  :Flashcards open
        Create or open `default_file`, including missing parent directories.
        The configured file must be inside `flashcards_dir`. Initial file
        creation uses the same guarded store as card and scheduling changes.

  :Flashcards check
        Check the whole collection. See |neorg-flashcards-data|.

  :Flashcards help
        Open the quick in-editor guide. The complete manual is available at
        |neorg-flashcards| with `:help neorg-flashcards`.

==============================================================================
GLOBAL KEYMAP                                   *neorg-flashcards-keymaps*

The plugin itself defines no global mappings. A normal Lua setup only needs:
>
  vim.keymap.set("n", "<leader>nc", "<cmd>Flashcards<CR>",
    { desc = "Open flashcards" })
<

Hub, review, and form keys are buffer-local. The NVF module creates the same
single mapping when `keymaps.enable = true`.

FLASHCARD HUB                                       *neorg-flashcards-hub*
                                               *neorg-flashcards-overview*

|:Flashcards| opens a full tab with Overview, Cards, and Stats pages. Wide
windows use two columns; narrow windows stack the panels. The winbar marks the
active page and keeps compact contextual key hints visible even when Neovim
uses a global statusline. Press `?` for the complete key list for the current
page.

Common keys:

  1 / 2 / 3       Overview / Cards / Stats
  Tab / Shift-Tab next / previous page
  Ctrl-W then w   focus the other pane; clicking a pane also focuses it
  j / k, Up / Down
                    select in the primary list; otherwise scroll
  Ctrl-D / Ctrl-U  scroll the focused pane by half a page
  PageDown / PageUp
                    scroll the focused pane by half a page
  gg / G            first/last item, or top/bottom of the focused pane
  ?               contextual key help
  H               quick plugin guide
  d / A           review due / review all active cards
  c               collection check
  R               reload the collection
  q               close the hub
  Esc             clear Cards search/filter first, then close

Navigation acts on the focused pane. In Overview and Cards, j / k changes the
selection in the primary pane and scrolls in the secondary pane. Stats scrolls
whichever pane is focused.

Overview groups cards by tag and keeps due review as the primary action:

  Enter           review the complete due queue
  r               review due cards in the selected tag group
  j / k           select the next / previous card
  a               add a card to `default_file`
  p / e           preview / edit the selected card

Cards is a searchable browser for the entire collection:

  /               search card text, tags, source, dates, and states
  f               choose a timing, lifecycle, or availability filter
  o               cycle due, front, state, and source sorting
  X               clear search and filter
  j / k           select the next / previous card
  Enter / r       review the selected active card
  x               suspend or resume the selected card
  b               bury until tomorrow or unbury the selected card
  D               confirm and delete the selected source block
  p / e           preview / edit the selected card

Invalid blocks, including every copy of a duplicate stable ID, appear as
`[INVALID]` rows. They remain searchable and have an `invalid` filter. Press
`e` to repair the source or `D` to delete that exact block; review, suspend,
and bury actions stay disabled.

Deletion checks that the parsed source has not changed and works through a
loaded buffer when present. A dirty source remains dirty and must be written
manually, leaving normal buffer undo available. For an unloaded source, the
previous complete source is saved to `<source>.flashcards-backup` before the
source is atomically replaced; the next unloaded-source deletion replaces that
backup. Historical review events are retained in `reviews.jsonl`.

For valid cards, `e` opens the same structured, value-only composer used for
creation and preserves the ID and scheduling metadata. Invalid blocks open as
raw source so their structure can be repaired directly.

Stats combines activity and collection analytics. Use `d` for due review,
`A` for an active-card cram session, or `R` to refresh its data. Both Stats
panes use the common scrolling keys above. Heatmap cells vary both their glyph
and their theme-linked activity highlight, so color is not the only signal.

==============================================================================
REVIEW                                             *neorg-flashcards-review*

Review keys are local to the floating review window:

  Space / Enter   reveal the answer; a revealed card must be rated
  j / k           browse next / previous pending card
  ?               shortcuts for the current review state
  h               show a progressively larger answer hint
  t               type and check an answer
  1               Again: save score 1 and retry once later this session
  2               Hard: save score 2 and remove the card from the queue
  3               Good: save score 3 and remove the card from the queue
  u               undo the latest accepted rating
  b               bury until tomorrow and remove from this session
  x               suspend and remove from this session
  e               edit the card in the structured composer
  q / Esc         close review

Pressing 1, 2, or 3 before reveal only reveals the answer. Press the rating
again after checking it. The revealed view shows the next interval for all
three ratings.

Again requeues a card only once per session, so the queue is finite. When the
queue is empty, a completion screen reports elapsed time, ratings, retries,
hints, buried cards, and suspended cards. `u` can still undo the last rating
from that screen.

Rating labels use NeorgFlashcardsAgain, NeorgFlashcardsHard, and
NeorgFlashcardsGood. They link to the theme's DiagnosticError,
DiagnosticWarn, and DiagnosticOk groups by default and can be changed through
`ui.rating_highlights`.

Ratings update an already loaded, modified source buffer without writing over
its unsaved edits. The matching JSONL history event waits in memory until you
save that source. Undoing the rating before the save removes the queued event.
A source changed after review collection is rejected instead of risking an
update to the wrong card.

COLLECTIONS AND CARD FORMAT                 *neorg-flashcards-card-format*
                                           *neorg-flashcards-collections*

Keep one or more `.norg` files under `flashcards_dir`. Collection commands
scan that directory recursively. Use |:Flashcards| `review file` for the
current chapter, `review tag grammar` across chapters, or `review all` for an
active-card collection cram session.

The collection root is also the write boundary. The composer and
`default_file` cannot target a path outside it. A running setup also refuses a
different directory that later appears at the configured root path.

Cards are plain Neorg blocks:
>
  @flashcard japanese
  id: fc_0123456789abcdef01234567
  japanese: 勉強
  reading: べんきょう
  english: study
  tags: jlpt vocab
  score: 2
  reviewed: 2026-07-01
  due: 2026-07-02 08:30
  interval: 0.5
  ease: 2.5
  reps: 6
  lapses: 1
  lifecycle: review
  availability: active
  @end
<

Every card needs a unique `id:` plus its schema fields marked
`required = true`; the composer creates the ID automatically. Ratings maintain
`score`, `reviewed`, `due`, `interval`, `ease`, `reps`, `lapses`, and
`lifecycle`. Bury and suspend actions maintain `availability`; a buried card
also gets an `available_at` timestamp.

==============================================================================
SCHEDULING                                   *neorg-flashcards-scheduling*

Ratings use a small SM-2-style rule set:

  1 Again   due after `again_minutes` (default 10); ease drops by 0.2
  2 Hard    interval grows by 1.2, starting at `hard_hours` (default 6)
  3 Good    interval grows by ease, starting at `good_days` (default 3)

Hard and Good intervals cannot exceed `max_interval_days` (default 365).

The hub presents three independent state axes:

  Lifecycle    new, learning, review, relearning
               Inferred when absent and written after ratings.

  Timing       due, overdue, scheduled
               `due` is absent or reached today, predates today, or is still
               in the future.

  Availability active, suspended, buried
               Controls whether normal due review can select the card.

Suspended cards remain outside due review until resumed. A buried card is
treated as active again after `available_at`; the built-in bury action uses
midnight tomorrow.

HEALTH, HISTORY, AND STATS                         *neorg-flashcards-data*

Every v0.2 card needs a stable, collection-unique `id:`. The composer creates
one automatically. ID-less v0.1 blocks remain visible as invalid cards but
cannot be reviewed. There is no automatic migration command; back up and
convert the blocks before switching versions. See |neorg-flashcards-upgrade|.

`:Flashcards check` reports parser and schema failures, missing and duplicate
IDs, duplicate fronts, malformed due dates or numeric fields, invalid
lifecycle values, and leeches. The leech threshold is configurable and
defaults to eight lapses. Invalid schema blocks and every copy of a duplicate
ID are excluded from review but remain visible on the Cards page for repair.
Other warnings do not make an otherwise valid card unreviewable.
`:checkhealth neorg_flashcards` reports the same setup and collection health
through Neovim's health UI.

Persisted ratings and card-state changes append versioned JSON events to
`reviews.jsonl` under `flashcards_dir` (or `history_file` when configured).
Events can carry card ID, rating, timestamp, duration, hint use, scheduling
states, and session context. Undo appends a compensating rating event instead
of rewriting the ledger. When the source buffer is already modified, matching
events are queued until that source is saved; undo before the save cancels its
pending rating. A failed history append stays in a durable outbox under
Neovim's state directory and is retried on later writes, focus, setup, and
exit. Print its directory with:
>
  :lua print(vim.fn.stdpath("state") .. "/neorg-flashcards/outbox")
<

Stats includes total and today's reviews, streak, 7/30/90-day retention,
30-day answer distribution, lifecycle and availability counts, leeches,
median answer time, an estimated due workload, a responsive activity heatmap,
and a seven-day forecast. It also lists the largest tag groups and the cards
with the lowest saved rating.

CLOZE AND TYPED ANSWERS                            *neorg-flashcards-cloze*

Any field may contain Anki-style cloze markers:
>
  @flashcard japanese
  id: fc_cloze_tokyo
  japanese: 東京は{{c1::日本}}の首都です
  english: Tokyo is the capital of {{c1::Japan|country}}
  @end
<

Before reveal, a marker shows as `[...]`, or `[country]` when it has a hint.
After reveal, it unwraps to the answer. Press `t` during review to compare a
typed answer with the reveal fields using UTF-8-aware fuzzy matching. You
still choose the rating yourself.

TROUBLESHOOTING                         *neorg-flashcards-troubleshooting*

`:Flashcards` is missing ~
Confirm that the plugin is installed and setup() completed. For lazy.nvim,
open `:Lazy` and inspect `:messages`. For a native optional package, run
`packadd luixbits-neorg-flashcards.nvim` before requiring the Lua module.

setup() reports an error ~
Read the complete error in `:messages`. Compare the configuration with
|neorg-flashcards-configuration|. `default_file` must be a .norg file inside
`flashcards_dir`, and Neovim must be able to create and write the root.

The hub has no cards ~
Save a .norg file under `flashcards_dir`, press `R`, then run
`:Flashcards check`. Invalid blocks are visible on Cards with the `invalid`
filter.

Nothing is due ~
Normal review includes new, due, active cards. Open Stats for the next due
time, or press `A` for an explicit all-active-card cram session.

The collection root moved or was replaced ~
Restore the configured directory. After an intentional move, update the paths
and call setup() again, or restart Neovim, so the new root identity is pinned.

Neorg syntax or concealing is missing ~
The flashcard UI works without Neorg. If Neorg was intended, confirm that it
loaded and run `:checkhealth neorg`.

A history or outbox warning persists ~
Check write access to reviews.jsonl and Neovim's state directory. Focus or
restart Neovim to retry. Inspect the outbox path shown in
|neorg-flashcards-data|; do not delete pending events as a first repair.

A card was deleted by mistake ~
For a loaded source, use normal buffer undo before closing it. For an unloaded
source, inspect `<source>.flashcards-backup`. Close Neovim and compare the
backup with the current file before restoring the older complete source.

==============================================================================
RELEASE SCOPE AND UPGRADE                         *neorg-flashcards-upgrade*

Version 0.2 targets Neovim 0.10.4 or newer on Linux and macOS. Windows path
handling is best effort. This release supports one configured collection, one
local history ledger, custom schemas, and the built-in three-rating scheduler.
Named collections, daily quotas, scheduler adapters, audio, sync, and import
or export tools are not part of 0.2.

The v0.1 `:NeorgFlashcard*` commands and suffix keymaps were removed. No
compatibility aliases remain. Replace them with |:Flashcards| routes and one
optional global hub mapping before updating. Rename the setup option
`languages` to `schemas`; NVF users must rename `languagePresets` to
`schemaPresets`. Before switching, back up the collection and manually convert
every v0.1 card to the canonical v0.2 fields with a unique `id:`. Then run
`:Flashcards check` before reviewing.

The complete command mapping and path checks are in `docs/UPGRADING.md` in the
plugin repository.

LUA API                                           *neorg-flashcards-lua-api*

The primary entry points are public functions on the plugin module:
>
  local flashcards = require("neorg_flashcards")
  vim.keymap.set("n", "<leader>nc", flashcards.overview,
    { desc = "Open flashcards" })
<

Result contracts:

- setup() returns true after valid configuration and errors on invalid
  options.
- UI and session functions return a boolean. True means the synchronous
  request was accepted; false means it was rejected or had no effect. For
  `vim.ui` prompts, true only means the prompt started; its callback receives
  the later answer.
- Source mutations return `ok, message, persisted`. `ok` says whether the
  change was accepted. `message` is nil when nothing needs explaining;
  otherwise it describes the result, warning, or error. A successful false
  `persisted` value means an open modified buffer still needs to be saved.
  Failed mutations always return `persisted = false`.
- Queries return data. Validation returns status, cards, and diagnostics.
- command() returns every result from the routed function. |:Flashcards|
  ignores those values.

                                                  *neorg-flashcards-functions*
setup({opts})             Configure and return true; invalid options error.
                          See |neorg-flashcards-setup|.
command({args})           Dispatch |:Flashcards| routes and return the result.
open_flashcards()         Create or open `default_file`.
add_kind({kind})          Add in the current collection `.norg`, or in
                          `default_file` from a non-`.norg` buffer or the hub.
add_to_default({kind})    Card form targeting `default_file`.
validate_file()           Return ok, valid cards, and current-buffer errors.
validate_collection()     Return ok, cards, health issues, and parser/history
                          diagnostics.
review_all()              Review all active, valid collection cards.
review_due()              Review due and new active cards, oldest first.
review_file()             Review the current file.
review_tag({tag})         Review one tag; prompt when omitted.
review_score({score})     Review an again/hard/good/new rating bucket.
overview({opts})          Open the hub; view is overview/cards/stats.
cards() / stats()         Open the corresponding hub page.
close_review()            Close the review popup.
flip_or_next()            Reveal the current answer.
next_card()               Browse the next pending card.
previous_card()           Browse the previous pending card.
rate_current({score})     Rate 1/2/3; return ok, message, persisted.
edit_current_card()       Edit the current valid card in the card form.
type_answer()             Typed-answer mode for the current card.
hint_current()            Reveal the next progressive answer hint.
undo_last_rating()        Undo the latest rating; return the mutation triple.
bury_current()            Bury until tomorrow; return the mutation triple.
suspend_current()         Suspend the card; return the mutation triple.
get_review_state()        Return a copy of the review session state.
toggle_suspend({card})    Toggle suspension; return the mutation triple.
edit_card({card}, {context})
                          Edit in the form; `context.invalid = true` opens
                          source for structural repair.
delete_card({card})       Delete the exact source block; return the mutation
                          triple. The low-level call does not confirm.
bury_card({card})         Bury until tomorrow; return the mutation triple.
toggle_bury({card})       Toggle burial; return the mutation triple.
open_card({card})         Open a parsed card at its source block.
help()                    Open the quick guide.
