SETUP                                               *neorg-flashcards-setup*

Requirements:

  Neovim 0.10.4 or newer
  A writable directory for each flashcard collection

Neorg is optional. Source files still use the .norg suffix because that is
the format scanned by the plugin. Without Neorg they are ordinary text; the
workspace, composer, review window, and statistics remain available.

Minimal setup:
>
  local presets = require("neorg_flashcards.presets")

  require("neorg_flashcards").setup({
    default_collection = "japanese",
    collections = {
      japanese = {
        label = "Japanese",
        path = vim.fn.expand("~/notes/flashcards/japanese"),
        default_file = "cards.norg",
        default_card_type = "japanese",
        schemas = presets.only("japanese"),
      },
    },
  })
<

After setup, run |:Flashcards|. Press `a` to add a card, `Ctrl-S` to save it,
and `Enter` in Overview to review cards due now. Press `?` in the workspace,
composer, or review window for current shortcuts. In contextual help, `?`
closes the popup.

COLLECTIONS AND CONFIGURATION             *neorg-flashcards-configuration*

A collection owns one directory, its card types, scheduling settings, and one
review-history ledger. Separate collections keep unrelated subjects out of
each other's queues and statistics.

Example with Japanese and computer science:
>
  local presets = require("neorg_flashcards.presets")

  require("neorg_flashcards").setup({
    default_collection = "japanese",
    collections = {
      japanese = {
        label = "Japanese",
        path = vim.fn.expand("~/notes/flashcards/japanese"),
        default_file = "inbox.norg",
        default_card_type = "japanese",
        schemas = presets.only(
          "japanese",
          "japanese_production",
          "japanese_kanji",
          "japanese_sentence"
        ),
      },
      computer_science = {
        label = "Computer Science",
        path = vim.fn.expand("~/notes/flashcards/computer-science"),
        default_file = "inbox.norg",
        default_card_type = "question_answer",
        schemas = presets.only(
          "question_answer",
          "term_definition",
          "code_output"
        ),
      },
    },
  })
<

Top-level options:

  default_collection      Collection ID selected at startup; required.
  collections             Non-empty map of collection IDs; required.
  ui.show_shortcuts       Show compact shortcut ribbons; default true.
  ui.rating_highlights    Again, Hard, and Good highlight definitions.
  ui.heatmap_highlights   Activity definitions for levels 0 through 4.
  on_review               Optional observer called after a source persists.

Collection options:

  label                   Human name; defaults to the collection ID.
  path                    Root, recursive scan, and write boundary; required.
  default_file            .norg file inside path; default cards.norg.
  default_card_type       First/default configured card type; required.
  schemas                 Non-empty card-type map; required.
  history_file            .jsonl file inside path; default reviews.jsonl.
  scheduling              Per-collection scheduler overrides.
  leech_threshold         Lapse warning threshold; default 8.

Relative default_file and history_file values resolve from path. Collection
paths cannot overlap. Two collections cannot share the same ledger, including
through symlinks or hard links.

Collection and card-type IDs begin with a lowercase letter and contain only
lowercase letters, numbers, `_`, or `-`. Setup rejects unknown options and
invalid schemas rather than guessing what a misspelled setting meant.

Setup creates missing collection directories and pins their resolved identity
for the session. Moving, replacing, or retargeting one makes operations stop.
Run setup again, normally by restarting Neovim, after an intentional move.

Press `C` in the workspace to choose a collection. The active collection name
is shown in page headings. Switching is blocked while a composer or review is
open, keeping the current draft and session attached to their original data.

==============================================================================
PRIMARY COMMAND                                 *neorg-flashcards-commands*

                                                        *:Flashcards*
:Flashcards [route]
        Open Overview with no route. This is the plugin's only Ex command.
        Completion lists routes, review scopes, collection IDs, and card
        types where appropriate.

  :Flashcards overview
  :Flashcards cards
  :Flashcards stats
        Open the workspace on that page.

  :Flashcards collection [id]
        Choose a collection, or switch directly when [id] is supplied.

  :Flashcards add [type]
        Open the composer. One configured type opens directly; several types
        open a picker. Supplying [type] skips the picker.

        From a .norg file inside the active collection, the card is added at
        the cursor. From another buffer or the workspace, it is added to the
        active collection's default_file.

  :Flashcards review due
  :Flashcards review all
  :Flashcards review file
  :Flashcards review tag [tag]
  :Flashcards review score [again|hard|good|new]
        Start a due, cram, current-file, tag, or rating-bucket review. Missing
        tag and score arguments open a prompt. Buried and suspended cards are
        excluded from every normal queue.

  :Flashcards open
        Create or open the active collection's default_file.

  :Flashcards check
        Check parsing, schemas, stable IDs, scheduling values, leeches, and
        review history.

  :Flashcards help
        Open the short in-editor guide.

GLOBAL KEYMAP AND HELP                           *neorg-flashcards-keymaps*

The plugin creates no global mappings. Its workspace, composer, help, and
review mappings are buffer-local. A single optional entry point is enough:
>
  vim.keymap.set("n", "<leader>nc", "<cmd>Flashcards<CR>", {
    desc = "Open flashcards",
  })
<

The NVF module creates that one mapping only when keymaps.enable is true. Its
keymaps.prefix option is the exact key used to open |:Flashcards|.

Useful current shortcuts are visible in the workspace winbar and floating
window footers when ui.show_shortcuts is true. Set it to false to hide the
compact ribbons without disabling mappings or `?` help. The focused long-field
editor keeps its short apply/cancel footer because those controls are local to
that editor.

Every `?` window is searchable with Neovim's normal `/`. Use `n` and `N` for
the next and previous matches. The short plugin guide opened with `H` or
`:Flashcards help` is searchable in the same way.

WORKSPACE AND CARD CLINIC                            *neorg-flashcards-hub*

The workspace has Overview, Cards, and Stats pages in one tab. A wide Neovim
window uses two columns; a narrow one stacks the panes.

Common keys:

  1 / 2 / 3       Overview / Cards / Stats
  Tab / S-Tab     Next / previous page
  C               Switch collection
  ?               Current page keys
  H               Open the short plugin guide
  Ctrl-W w        Focus the other pane
  j / k           Select in the primary pane, or scroll the focused pane
  Ctrl-D / Ctrl-U Scroll half a page
  PageDown / Up   Scroll half a page
  gg / G          Top / bottom
  d / A           Review due / all active cards
  c               Check the collection
  R               Reload
  q               Close

Overview groups cards by tags and makes the due queue its primary action.
`r` reviews the selected tag group, while `a`, `p`, and `e` add, preview, or
edit a card.

Cards is the working list:

  /               Search card text, tags, type, source, date, and state
  f               Choose a state, Card Clinic, or card type
  o               Cycle due, front, state, and source sorting
  X               Clear search and view
  Esc             Clear an active view; otherwise close the workspace
  Enter / r       Review the selected active, valid card
  p / e           Preview / edit
  x               Suspend or resume
  b               Bury until tomorrow or unbury
  D               Delete the exact source block after confirmation

Invalid cards remain visible as [INVALID] and may be edited. A closed invalid
block may also be deleted; an unclosed block needs its missing @end first.
Invalid cards cannot be reviewed or scheduled. Deleting from an unloaded
source first saves the previous complete file as
<source>.flashcards-backup. Deleting from an open modified buffer leaves the
change unsaved for inspection or normal undo.

Card Clinic is a Cards view selected with `f`. It includes an active card when
its lapse count reaches leech_threshold, two of its last three reviews were
Again, its latest rating was Again, or two of its last three reviews used
hints. Undo events are respected; suspended and buried cards are excluded.

The detail pane shows non-redundant reasons for a card's inclusion and a
recall trail with the newest rating on the right. Stats uses the same evidence
in its Needs attention section.

==============================================================================
COMPOSER AND CARD TYPES                      *neorg-flashcards-composer*

The composer shows one protected row per field. Names, required marks,
placeholders, validation messages, and the target file are decorations, not
editable text. Backspace, word deletion, and Delete cannot cross a value's
boundary.

Insert-mode keys:

  Enter           Next field; save and return from the final field
  Tab / S-Tab     Next / previous field
  Ctrl-S          Save and return
  Ctrl-N          Save and start another card
  Esc             Return to Normal mode

Normal-mode keys:

  j / k           Select a field
  Enter / i       Edit the selected field
  Ctrl-S          Save and return
  Ctrl-N          Save and start another card
  ?               Show all form keys
  q / Esc         Cancel; confirm first when the draft changed

A multiline field appears as one protected preview row. Press Enter on it to
open a focused editor containing only the value. Ctrl-S applies the long text
to the parent draft; Esc cancels it. Changed text gets a discard confirmation.
Applying does not save the card until the parent composer is saved.

Bundled card types:

  japanese              Japanese recognition
  japanese_production   Produce Japanese from English
  japanese_kanji        Kanji reading and meaning
  japanese_sentence     Sentence translation and context
  chinese               Chinese recognition
  question_answer       General long-form questions
  term_definition       Terms, definitions, and examples
  code_output           Predict and explain output; code is never executed

A custom schema has label, front, and fields. Every field needs a key. Useful
field flags are required, reveal, multiline, and typed_answer. A typed_answer
field must also set reveal = true.
>
  local term = {
    label = "Term and definition",
    front = "term",
    fields = {
      { key = "term", title = "Term", required = true },
      {
        key = "definition",
        title = "Definition",
        required = true,
        reveal = true,
        multiline = true,
      },
      { key = "tags", title = "Tags" },
    },
  }
<

presets.only(...) raises when a preset name is unknown, so a typo cannot
quietly remove a card type.

==============================================================================
REVIEW                                             *neorg-flashcards-review*

Review-window keys:

  Enter / Space   Reveal the answer
  h               Show a progressive hint
  t               Type and compare an enabled answer
  1 / 2 / 3       Again / Hard / Good
  j / k           Browse pending cards
  u               Undo the latest rating
  b               Bury until tomorrow
  x               Suspend
  e               Edit the current card
  ?               Show keys for the current review state
  q / Esc         Close review

A rating pressed before reveal reveals first. Press it again after checking
the answer. The revealed view previews every next interval. Again requeues a
card once later in the current session, so Again cannot create an endless
retry loop.

Typed answers are for short values and exist only for card types with
typed_answer fields. Comparison ignores case, outer spaces, and repeated
whitespace, then chooses the closest enabled reveal value. A near miss aligns
Yours and Answer; a middle dot marks missing text so color is not required.
The result never selects a rating. Typed text and difference details stay in
memory for the current attempt and are not written to card source or review
history. The built-in prompt entry is removed from Neovim input history. A
custom vim.ui.input implementation controls any history of its own.

Anki-style cloze markers work in any field:

  {{c1::answer}}
  {{c1::answer|hint}}

They show as [...] or [hint] before reveal and as plain text afterward.

==============================================================================
STORED CARD FORMAT                            *neorg-flashcards-card-format*

Cards are plain @flashcard blocks:
>
  @flashcard japanese
  id: fc_0123456789abcdef01234567
  japanese: 勉強
  reading: べんきょう
  english: study
  notes: |
    Common noun and する verb.
    Often used in 勉強します.
  tags: jlpt-n5 study
  score: 2
  reviewed: 2026-08-22
  due: 2026-08-22 18:00
  interval: 0.25
  ease: 2.5
  reps: 4
  lapses: 1
  lifecycle: learning
  availability: active
  @end
<

Every card needs a collection-unique stable id and every schema-required
field. The composer creates the ID. Ratings maintain score, reviewed, due,
interval, ease, reps, lapses, and lifecycle. Bury and suspend maintain
availability and available_at.

Long values use `field: |`. Every content line starts two spaces beyond its
card directive; further indentation belongs to the value. An empty value line
contains those two storage spaces. @end aligns with @flashcard, including when
a card is below an indented Neorg node. There is no implicit continuation
syntax: a free-standing line is reported as invalid.

==============================================================================
SCHEDULING                                   *neorg-flashcards-scheduling*

The three ratings use these defaults:

  1 Again   10 minutes; ease -0.20, not below 1.30
  2 Hard     6 hours first; previous interval x 1.20 afterward
  3 Good     3 days first; previous interval x current ease afterward;
             ease +0.05, not above 2.80

Hard and Good intervals are capped at 365 days. Multiplication spaces out a
remembered card; the cap prevents unbounded growth. Again resets its delay to
ten minutes.

Every scheduling value is a positive finite number:

  again_minutes        10
  hard_hours            6
  good_days             3
  starting_ease         2.5
  min_ease              1.3
  max_ease              2.8
  max_interval_days   365

min_ease must not exceed starting_ease, which must not exceed max_ease.
good_days must not exceed max_interval_days.

Card state has three independent axes:

  Lifecycle     new, learning, review, relearning
  Timing        due, overdue, scheduled
  Availability  active, suspended, buried

Buried cards return at midnight the next day. Suspended cards stay out until
resumed. Review all ignores due time as an explicit cram mode, but still
excludes buried and suspended cards.

HEALTH, HISTORY, AND STATS                         *neorg-flashcards-data*

|:Flashcards| check and |:checkhealth| neorg_flashcards report parser and
schema errors, missing or duplicate IDs, malformed scheduling data, leeches,
and history problems. Every copy of a duplicate ID is excluded from review;
the plugin cannot safely decide which source owns that schedule and history.

Normal events are appended as versioned JSON objects to reviews.jsonl inside
their collection. Events include collection_id and card_type as well as stable
card identity, timestamps, ratings, scheduling snapshots, hint use, duration,
and session context. Undo appends a compensating event.

An older event without collection_id inherits the scope of its ledger. An
event explicitly naming another collection is reported and excluded from
analytics for the active collection.

When a source buffer has unsaved changes, its event waits in memory until the
source is written. Undo before that write removes the pending event. If the
source persisted but the ledger append failed, an outbox under stdpath(state)
keeps the event for retry on writes, focus, setup, and exit.

Stats includes totals, streak, 7/30/90-day retention, 30-day ratings, card
states, leeches, median answer time, estimated workload, an activity heatmap,
a seven-day forecast, tag sizes, and the Card Clinic attention list.

==============================================================================
THEME COLORS                                      *neorg-flashcards-colors*

Again, Hard, and Good link to DiagnosticError, DiagnosticWarn, and
DiagnosticOk by default. Heat levels link to NonText, Comment, DiagnosticHint,
DiagnosticInfo, and DiagnosticOk. These links follow the active colorscheme.

Override links or provide exact attributes when a theme makes them unclear:
>
  ui = {
    rating_highlights = {
      again = { fg = "#ff5f5f", bold = true },
      hard = { fg = "#e5c07b" },
      good = { fg = "#98c379" },
    },
  }
<

Overrides return after a colorscheme change. Labels, glyphs, and written state
also carry meaning, so color is never the only signal.

UPGRADE AND TROUBLESHOOTING                       *neorg-flashcards-upgrade*

Version 0.3 replaces the v0.2 single-collection setup. It does not register
compatibility options or old commands. Read docs/UPGRADING.md before updating
a working configuration.

Common problems:

  :Flashcards is missing
        Confirm the plugin loaded and setup() ran. Check :messages.

  setup() raises an error
        Read the full error. Unknown options are rejected. Check that every
        collection has path, default_card_type, and at least one schema.

  The workspace shows no cards
        Save a .norg file below the active collection path, press R, then run
        :Flashcards check. Also confirm the collection named in the heading.

  A due queue is empty
        Normal review includes active new and due cards. Use Stats for the
        next due time or A for the explicit all-active cram queue.

  A collection root moved
        Restore it, or update setup and restart Neovim so the new directory
        identity is pinned.

  A history/outbox warning persists
        Check write access to reviews.jsonl and stdpath(state). Focus or
        restart Neovim to retry. Do not delete queued events as a first fix.

  A card was deleted accidentally
        Use normal buffer undo for an open source. For an unloaded source,
        compare it with <source>.flashcards-backup before restoring.

LUA API                                           *neorg-flashcards-lua-api*

Commands call public functions on require("neorg_flashcards"):

  setup(opts)
        Validate and configure the workspace. Returns true; raises on invalid
        configuration.

  active_collection()
        Return a defensive copy of the active collection.

  select_collection(id) / choose_collection()
        Switch directly or open the collection picker.

  command(args?)
        Dispatch the same routes as |:Flashcards|.

  overview(opts?) / cards() / stats()
        Open the workspace. opts.view accepts overview, cards, or stats.

  open_flashcards()
        Create or open the active collection's default_file.

  add_kind(type?) / add_to_default(type?)
        Choose or directly open the composer. add_to_default ignores the
        current source file.

  validate_file()
        Return ok, valid_cards, errors for the current buffer.

  validate_collection()
        Return ok, cards, health_issues, diagnostics.

  review_due() / review_all() / review_file()
  review_tag(tag?) / review_score(score?)
        Start the corresponding finite review queue.

  close_review() / flip_or_next() / next_card() / previous_card()
  hint_current() / type_answer() / get_review_state()
        Control or inspect the active review session.

  rate_current(1|2|3)
  undo_last_rating() / bury_current() / suspend_current()
        Mutate the current review card.

  toggle_suspend(card) / bury_card(card) / toggle_bury(card)
  delete_card(card)
        Mutate a parsed card and return ok, message, persisted. delete_card is
        a low-level call and does not show the Cards-page confirmation.

  edit_current_card() / edit_card(card, context?) / open_card(card)
        Open a card in the composer or at its source.

  help()
        Open the short plugin guide.

UI-opening and control functions return whether the synchronous request was
accepted. A vim.ui prompt may return true before its callback receives a later
answer. active_collection() and get_review_state() return data; validation
calls return their documented status and diagnostics. Source mutations return
ok, message, persisted. A successful result with persisted=false changed an
open modified buffer that still needs saving.
